# Instagram Store Finder

Автоматический поиск Instagram-магазинов для предложения сайтов-каталогов.
Система сама находит аккаунты через публичную поисковую выдачу и накапливает их
в закрытой Google-таблице. Вводить список профилей вручную не нужно.

Нет фильтра по стране, городу, языку аккаунта или числу подписчиков.

## Что уже реализовано

- Поисковые запросы на 14 языках, с чередованием товарных ниш.
- Извлечение ссылок на профили, удаление дублей по username.
- Сохранение названия, поискового описания, источника и дат обнаружения.
- Прозрачная оценка признаков физического товара, торговли, заказов в Direct/WhatsApp.
- Google-таблица с русскими заголовками и статусами.
- Обновление автоматических полей без перезаписи контакта, демо, комментария и статуса работы.
- Продолжение следующей партии запросов при очередном запуске.
- GitHub Actions дважды в день и по кнопке **Run workflow**.
- Проверки на дубли, неправильные ссылки, посты вместо профилей, языки, ошибки
  источников, сохранность ручных полей и восстановление базы.

Ссылки на отдельные публикации/Reels не превращаются в угаданные аккаунты.
Текст поискового запроса не считается доказательством того, что профиль — магазин.
Если поисковик склеил несколько карточек, чужое описание не присваивается первому аккаунту.

## Google-таблица и запуск

Готовая таблица привязана через `config/destination.json`. Аккаунты и контакты
не записываются в публичный репозиторий, логи или открытые артефакты.

Для самостоятельной записи из GitHub Actions нужен сервисный аккаунт Google:

1. В Google Cloud создать проект и включить **Google Sheets API**.
2. Создать сервисный аккаунт, затем его ключ в формате JSON.
3. В таблице дать этому аккаунту доступ **Редактор** по `client_email` из JSON.
4. В GitHub **Settings → Secrets and variables → Actions → New repository secret**
   добавить **`GOOGLE_SERVICE_ACCOUNT_JSON`**: всё содержимое JSON-файла.
5. **Actions → Discover stores → Run workflow**, оставить `smoke` выключенным.

Пошаговая инструкция: [docs/google-sheets-setup.md](docs/google-sheets-setup.md).
Ключ не нужно присылать в чат или добавлять в файлы репозитория.
Таблица остаётся закрытой; публикация по ссылке не требуется.

При использовании другой таблицы можно установить секрет `GOOGLE_SHEET_ID`.
Нужны листы `Магазины` и `Служебное` и те же заголовки. Изменение структуры
без обновления кода приводит к остановке, а не записи данных в неправильные столбцы.

## Столбцы таблицы

| Автоматически обновляемые A:P | Ручные Q:T |
| --- | --- |
| Аккаунт, ссылка, название, ниша (гипотеза) | Статус работы |
| Результат проверки, оценка, описание | Контакт |
| Сайт, подписчики, страна, язык аккаунта | Ссылка на демо |
| Языки запросов, даты, источник, причины оценки | Комментарий |

Результат проверки: **Вероятно магазин** или **Нужно проверить**.
Это предположение по поисковой выдаче, а не подтверждение продажи.
Статус работы: **Новый, Проверить, Написал, Ответил, Демо готово, Купил, Не подходит**.

Даты — значения даты/времени, отображаются по Минску. Оценка — число.
Отсутствие сайта не определяется по отсутствию ссылки в сниппете: **Не проверен**.
Подписчики, страна и язык аккаунта остаются неизвестными, пока нет достоверного
обогащения. Языки запросов — языки поиска, не установленный язык магазина.

Служебный лист хранит позицию поисковой очереди. Не удаляйте его.
При повторном обнаружении сохраняются первая дата и ручные поля. При сортировке
используйте всю таблицу, не отдельный столбец. Не сортируйте строки во время записи
из Actions; между запусками сортировка допустима.

## Расписание и ограничения

Поиск запланирован примерно на **10:23 и 22:23 по Минску**
(`23 7,19 * * *` в UTC). GitHub может задерживать cron; после длительной
неактивности публичного репозитория расписание может отключаться.

По умолчанию: 14 запросов за запуск, до 20 результатов на запрос, пауза 3 секунды
между запросами. Это лимит обработки, не обещанное количество новых магазинов.
В форме **Run workflow** бюджет можно менять в пределах 1–100.

Стартовые языки: английский, испанский, португальский, русский, французский,
немецкий, итальянский, турецкий, арабский, индонезийский, польский, хинди,
японский и корейский. Это стартовый набор запросов, не ограничение языка аккаунта.
Ниши: украшения, одежда, свечи, сумки и керамика. Новые ниши/языки добавляются
в `config/queries.json`.

Всего 70 стартовых запросов. После полного прохода меняется страница выдачи
(1 → 2 → 3 → 1). Аккаунты не исключаются по размеру или географии.

Неиндексируемые аккаунты поисковики не покажут. Описания иногда скрыты или
устарели. В этом случае кандидат остаётся **Нужно проверить**. Если все источники
недоступны или нет ни одной ссылки на профиль, запуск завершается ошибкой,
а не успешным пустым сбором. Существующая база не очищается.

## Источники и оценка

DDGS 9.11.4 последовательно проверяет `bing`, `brave`, `duckduckgo`. При ошибке
или пустом ответе используется следующий источник. Нет платного API, входа
в Instagram, решения CAPTCHA и смены IP. Учитывается обычный сетевой
`HTTPS_PROXY` окружения, если он задан.

| Признак в названии/описании | Баллы |
| --- | ---: |
| Магазин, продажа, доставка | +25 |
| Заказы через Direct/WhatsApp | +35 |
| Физические товары | +30 |
| Агентство, курсы, неподходящие услуги | −45 |

«Вероятно магазин»: есть физический товар и коммерческий признак без найденных
признаков неподходящих услуг. Остальные сохраняются для проверки. В первой версии
нет автоматической рассылки, создания демо или импорта товаров.

## Локальный тест

Для ежедневного сбора без включённого Mac подключите
[облачную проверку на Apify Free](docs/cloud-setup.md). Она использует существующую
Google-таблицу, проверяет до 20 профилей за запуск и допускает только бесплатный
план. Первичная настройка — один секрет `APIFY_API_TOKEN` в GitHub.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m store_finder run --smoke --query-budget 4 --results-per-query 10
```

`--smoke` печатает только счётчики, найденные аккаунты не сохраняет.
Каждый push в `main` автоматически запускает такой небольшой сетевой тест
и отдельные тесты кода. **Actions → Discover stores → Summary** показывает
число запросов, профилей, предполагаемых магазинов и ошибок источников.
Открытый артефакт `discovery-summary` содержит только агрегированные счётчики.

## Необязательная зашифрованная копия

Можно добавить `RESULTS_ENCRYPTION_KEY` для резервной копии базы в артефакте
`leads-encrypted`. Для Google-таблицы этот ключ не нужен.

Сгенерировать ключ на Mac без установки пакетов:

```bash
python3 -c 'import base64,secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())'
```

После скачивания артефакта и установки переменной `RESULTS_ENCRYPTION_KEY`:

```bash
python -m store_finder export /path/to/leads.fernet --output output/export
```

Получатся `state.json` и CSV с русскими заголовками. Ключ нужно сохранить отдельно;
его изменение делает старые архивы недоступными. Артефакты хранятся 90 дней.
Для полностью локальной работы можно использовать только этот ключ без Google:

```bash
python -m store_finder run --query-budget 14 --results-per-query 20
```
# Проверка профилей и сайтов

После поиска парсер проверяет до 12 аккаунтов через Chromium (Playwright): читает
JSON-ответы страницы и делает один `fetch` в контексте Instagram. При 401/403/429
повторные API-запросы в этом запуске прекращаются. Доступные метаданные страницы
используются как резервный источник подписчиков. Вход и обход ограничений не выполняются.

Сведения появляются в русских колонках U:AS; пользовательские Q:T сохраняются.
Подписчики из поискового индекса отмечены отдельно, округление K/M тоже сохраняется.
Отсутствие ссылки подтверждается только полными данными профиля. При закрытой странице
сайт и актуальность публикаций остаются неизвестными.

Сайты проверяются с учётом перенаправлений, ошибок DNS/TLS, HTTP-кодов и заглушек.
403, CAPTCHA и 5xx не считаются подтверждённой нерабочей ссылкой. Нерабочий сайт
повышает приоритет и добавляет повод предложить готовую витрину. Работающий сайт,
закрытый аккаунт и подтверждённая неактивность отмечаются как неподходящие для
предложения новой витрины. Порог активности — 90 дней; старые закреплённые посты
сами по себе не доказывают неактивность. Страны и языки не ограничиваются.

Настройки: `config/qualification.json`. Порог подписчиков по умолчанию мягкий;
жёсткие минимальное/максимальное значения отключены. Полные профили перепроверяются
через 7 дней, частичные — через день.

```sh
pip install -r requirements.txt
python -m playwright install --with-deps chromium --only-shell
python -m store_finder run --enrich-only --enrichment-budget 12
```

Workflow **Check existing profiles** позволяет перепроверить уже найденные строки
без нового поиска. Обычный плановый запуск также выполняет обогащение.
