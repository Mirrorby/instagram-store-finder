# Сбор участников через GitHub Actions

Mac для сбора не нужен. После разовой авторизации все запуски выполняются
на GitHub, участники сохраняются в существующей Google-таблице.

## Разовая настройка

В репозитории откройте Settings → Secrets and variables → Actions.
Нужны Repository secrets:

| Secret | Значение |
| --- | --- |
| `TELEGRAM_API_ID` | api_id приложения с https://my.telegram.org → API development tools |
| `TELEGRAM_API_HASH` | api_hash того же приложения |
| `TELEGRAM_SESSION` | Авторизованная StringSession, см. ниже |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Уже используемый JSON сервисного аккаунта Google |
| `GOOGLE_SHEET_ID` | Необязательно: ID другой таблицы вместо config/destination.json |

JSON Google уже используется Instagram-сборщиком в Actions: повторно скачивать
ключ на Mac не нужно. Сервисный аккаунт должен иметь доступ редактора к таблице.

### Первый вход в Telegram — тоже в браузере

Actions не имеет интерактивного терминала для ввода кода входа. Один раз
создайте сессию в GitHub Codespaces; устанавливать что-либо на Mac не нужно.
Codespaces — отдельный сервис с собственными квотами и возможной оплатой.
Перед созданием проверьте доступную квоту в аккаунте GitHub.

1. Откройте репозиторий → Code → Codespaces → Create codespace on main.
2. В его браузерном терминале выполните:

   ```sh
   python -m pip install -r requirements-telegram.txt
   python -m store_finder.telegram_login --qr
   ```

3. Введите api_id и api_hash. Откройте `.auth/telegram-login.png` в файловой
   панели Codespaces. На телефоне: Telegram → Настройки → Устройства →
   Подключить устройство, отсканируйте QR. При включённой 2FA введите её
   пароль в терминале. Код в сообщении не требуется. QR удаляется после
   завершения/истечения. Если истёк — запустите команду заново.
   Для входа по номеру используйте команду без `--qr`: она покажет
   способ доставки кода, сообщённый сервером. Не повторяйте запросы подряд
   при FloodWait/PhoneNumberFlood. Вводите секреты только в личном терминале.
4. В файловой панели Codespaces откройте файлы в `.auth/`:
   `TELEGRAM_API_ID.txt`, `TELEGRAM_API_HASH.txt`, `TELEGRAM_SESSION.txt`.
   Каждый файл содержит значение соответствующего Repository secret.
   Скопируйте значения в Secrets репозитория. Сессия не выводится в логи.
5. Удалите Codespace после переноса значений. Файлы `.auth/` исключены из Git.

Не вводите код Telegram, пароль 2FA или сессию в поле запуска Actions.
Сессия даёт доступ к аккаунту; не публикуйте её. При отзыве сеанса через
Telegram → Настройки → Устройства создайте новую сессию и замените Secret.

## Запуск сбора

1. Откройте Actions → **Collect Telegram members** → **Run workflow**.
2. Выберите `main`.
3. В поле групп укажите ссылку, например `https://t.me/yardsalemd`.
   Можно до 20 групп через пробел, запятую или перевод строки.
4. Нажмите Run workflow. По завершении Summary содержит количество полученных,
   добавленных и обновлённых строк и ссылки на соответствующие листы.

Запускается только вручную: расписания и отправки сообщений нет.
Одновременно работает один сборщик; следующий запуск ждёт завершения текущего.
В публичные логи попадают агрегированные числа и ссылка на лист, но не список
участников, пригласительная ссылка, сессия или Google-ключ.
Контакты не загружаются в GitHub Artifacts и не коммитятся в репозиторий.

## Листы и повторный сбор

Для каждого чата создаётся отдельный лист с названием чата. Недопустимые
символы заменяются, длинное название сокращается до 100 символов. При
совпадении названий добавляется ID группы; другие листы не перезаписываются.
Привязка по Telegram ID хранится в метаданных Google Sheets: переименование
чата или смена его публичной ссылки обновляет прежний лист.

- A:L — сведения Telegram: ID, имя, username, ссылка на профиль, доступ к
  профилю, бот, удалённый аккаунт, ID и ссылка группы, первая и последняя
  даты наблюдения, полнота последнего сбора. Время по Минску.
- M:R — ручные поля: статус, товары, дата первого сообщения, следующий
  контакт, демо и заметки. Для существующих участников не записываются.
- Дубли исключаются по Telegram ID внутри группы. Новые участники добавляются
  со статусом «Новый». Один человек в разных группах есть в каждом листе.
- Боты и удалённые аккаунты помечаются; их можно отфильтровать.
- При отсутствии username ссылка на профиль пустая: надёжный переход из
  таблицы по одному Telegram ID не гарантируется.
- Пропавшие из новой выборки контакты не удаляются. Дата последнего наблюдения
  не означает подтверждённый выход из группы.

Не меняйте заголовки, Telegram ID и ID группы. Сортируйте весь диапазон A:R
вместе. Не сортируйте и не вставляйте строки во время выполнения Actions.
После сетевой ошибки записи повторите сбор — ID предотвращают дубли.

## Ограничения Telegram

Используется пользовательский аккаунт, а не токен бота. Список участников
должен быть доступен этому аккаунту. Если нужны права администратора,
скрипт сообщит об этом. Приватная ссылка работает только для группы, в которую
аккаунт уже вступил; скрипт сам не вступает в группы. Пригласительная ссылка
не сохраняется в таблицу.

Telegram может вернуть часть участников. Если получено меньше заявленного
общего количества или общий размер неизвестен, выборка явно помечается
как неполная/неподтверждённая. Даже совпадение чисел — только сравнение на
момент сбора: состав группы может измениться. Ошибка чтения группы не
запускает запись её участников. FloodWait останавливает сбор с указанием,
через сколько секунд можно повторить; уже завершённые группы сохраняются.
