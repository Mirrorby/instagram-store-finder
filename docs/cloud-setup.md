# Облачная проверка без включённого Mac

Поиск аккаунтов работает в GitHub Actions. Данные профилей собирает официальный
Actor `apify/instagram-profile-scraper`: подписчики, описание, ссылки профиля,
последние публикации и их даты. Собственную сессию Instagram передавать не нужно.
Проверку сайтов выполняет наш код в GitHub Actions, с отдельным Chromium только
для повторной проверки ограниченных страниц. Cookies Instagram туда не попадают.

## Бесплатный план

На 13.10.2026 Apify Free предоставляет $5 кредита в месяц без привязки карты.
Обычный профиль стоит $0.0026; платный модуль About account выключен.
20 профилей ежедневно — до 620 профилей за 31 день, ориентировочно $1.61
кредита по опубликованной цене. Повторные проверки входят в это количество.
Использование других сервисов Apify также расходует общий кредит.

Перед запуском код проверяет, что план имеет `tier: FREE`, базовую цену $0
и `isPaying: false`. На платном или неизвестном плане Actor не запускается.
Каждый запуск ограничен `maxTotalChargeUsd: 0.10`, временем 300 секунд и
партией до 20 аккаунтов. При исчерпании кредита Free-план приостанавливает работу.
Система не меняет подписку, не добавляет карту и не увеличивает лимиты сама.

## Подключить Apify

1. Зарегистрируйтесь в https://console.apify.com/ на **Free**, без банковской карты.
2. В **Settings → API & Integrations** найдите личный API token.
3. В GitHub откройте **instagram-store-finder → Settings → Secrets and variables → Actions**.
4. Добавьте секрет **APIFY_API_TOKEN** со значением токена Apify.
5. Уже настроенный `GOOGLE_SERVICE_ACCOUNT_JSON` используется для записи в ту же таблицу.

Токен не присылайте в чат и не добавляйте в код. Удалённые HTTP-ошибки
не печатаются целиком: публичные логи содержат только счётчики и безопасный статус.

## Первая проверка

В **Actions → Cloud profile checks → Run workflow** выберите:

- `limit`: **5** для первого теста;
- `force`: **false**.

После запуска проверьте **Summary**. `updated` показывает число сохранённых
аккаунтов, `missing_results` — сколько профилей сервис не вернул. На Free
в эту первую партию расходуется часть включённого кредита. Пока токен не добавлен,
живой сбор не может быть проверен; тесты кода не заменяют этот запуск.

Расписание GitHub уже подготовлено на **11:30 Europe/Minsk** ежедневно.
GitHub может задерживать календарные запуски. Внешний cron-job.org запускает тот
же workflow через API, а расписание GitHub служит резервом.

Перед запросом к Apify в скрытый лист **Служебное**, A7:B7, записывается
`cloud_last_attempt`. Если с предыдущей попытки прошло меньше 20 часов,
повторная задача ничего не заказывает. Эта защита действует также после ошибки:
сетевой таймаут при запуске Actor не доказывает, что Actor не был запущен.
POST запуска никогда не повторяется автоматически.

Для явного ручного повторного теста есть `force: true`: он расходует дополнительный
кредит. Повседневное расписание всегда оставляйте с `force: false`.

## cron-job.org

Создайте отдельную задачу, не меняя задачи других проектов:

| Настройка | Значение |
| --- | --- |
| Название | Instagram — проверка магазинов |
| URL | `https://api.github.com/repos/Mirrorby/instagram-store-finder/actions/workflows/cloud.yml/dispatches` |
| Метод | POST |
| Расписание | Ежедневно, 11:30 |
| Часовой пояс | Europe/Minsk |
| Header Accept | `application/vnd.github+json` |
| Header Content-Type | `application/json` |
| Header X-GitHub-Api-Version | `2022-11-28` |
| Header Authorization | `Bearer ВАШ_GITHUB_TOKEN` |

Тело запроса:

```json
{"ref":"main","inputs":{"limit":"20","force":false}}
```

Для Authorization нужен fine-grained token GitHub, ограниченный репозиторием
`Mirrorby/instagram-store-finder`, с **Actions: Read and write**. Токен Apify
для этого заголовка не подходит. Значение GitHub token вводите непосредственно
в cron-job.org; не вставляйте его в URL, репозиторий или чат. Создание/добавление
этого доступа выполните сами в своих настройках аккаунтов.

Тестовый запрос должен вернуть **HTTP 204**. Это подтверждает принятие задания
GitHub, а не успех сбора: затем проверьте сам новый запуск Cloud profile checks.
Интервал не надо ставить каждую минуту — ежедневной задачи достаточно.

## Сохранение результатов

Результаты сохраняются в существующие строки листа **Магазины**: C, E:F, H:I,
P и U:AS. Русские заголовки, ручные Q:T, ссылки на профили, поисковые описания,
страна/язык, даты обнаружения и курсор поиска сохраняются. Перед записью таблица
перечитывается: сортировка не приводит к записи в чужую строку. Удалённые аккаунты
не создаются заново; ручные статусы **Купил / Не подходит** пропускаются.

Полные свежие данные Apify повторно проверяются через 7 дней, неполные —
не раньше следующего дня. Сначала берутся наиболее давно проверенные аккаунты.
При частичном ответе прошлые подписчики/дата остаются в строке, но новая полнота
проверки отмечается отдельно. Подтверждённое отсутствие ссылки очищает старый сайт.
Ошибка доступа не превращает магазин автоматически в подходящего кандидата.

Сайт с 404/410 или заглушкой может стать поводом предложить витрину;
401/403/429 остаётся **Проверка ограничена**, DNS/соединение — **перепроверить**.
Обычная reCAPTCHA в контактной форме не означает блокировку рабочего магазина.

Открытый артефакт `cloud-summary` содержит только агрегированные счётчики.
Профили, описания, даты и ссылки остаются в закрытой Google-таблице и в аккаунте
Apify, через который выполнялся сбор; в публичный репозиторий они не выгружаются.
