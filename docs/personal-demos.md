# Персональные демо из Instagram на Mac

Цепочка: очередь магазинов → профиль и фотопубликации → локальные копии фото →
демо Delokay → проверка публичных данных и фото → текст первого сообщения.
Команда не отправляет Direct, email или другие сообщения.

## Первый запуск: только сбор и локальный просмотр

В обычном Chrome откройте Instagram с рабочей сессией. В
`chrome://inspect/#remote-debugging` включите **Allow remote debugging**.
Подробности подключения: [local-test.md](local-test.md).

В существующей копии проекта:

```sh
git fetch origin
git switch feat/personalized-demos
git pull --ff-only
source .venv/bin/activate
python -m pip install -r requirements-local.txt
python -m store_finder demos --accounts the.jewelry.shop --limit 1 --language ru --currency BYN
```

В новой копии сначала:

```sh
git clone --branch feat/personalized-demos https://github.com/Mirrorby/instagram-store-finder.git
cd instagram-store-finder
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-local.txt
```

В режиме существующего Chrome устанавливать отдельный Chromium не требуется.
Если Chrome показывает локальный адрес сервера, добавьте к команде:

```sh
--cdp-endpoint ws://127.0.0.1:9222/devtools/browser
```

Откройте `output/demos/the.jewelry.shop/preview.html`. Это страница проверки
собранных данных, а не ссылка для клиента. В папке также будут:

| Файл | Содержимое |
| --- | --- |
| `source.json` | Данные профиля и фотопубликаций до скачивания изображений |
| `bundle.json` | Название, био, ссылки, логотип, фото, подписи, даты и подготовленный импорт |
| `assets/` | Локальные копии логотипа и фотографий |
| `publish.json` | Прогресс создания магазина и загрузки фото; появляется при публикации |
| `first-contact.txt` | Текст со ссылкой на проверенное демо; появляется после успешной публикации |
| `error.json` | Последняя ошибка; успешный повтор может сделать её неактуальной |

Папка `output/` исключена из git. Сессии Chrome и cookies не экспортируются.
Файлы с данными создаются с правами 600, папки — 700. Храните папку целиком:
она нужна для продолжения импорта без дублей.

## Что извлекается

- Username, название, полное био, внешние ссылки, ссылка на аватар/логотип.
- До 6 последних **полученных** фотопубликаций; число меняется через `--products 6`.
- Дата, исходная ссылка, подпись до 5000 символов и до 8 фотографий публикации.
- Карусель становится одним товаром; из смешанной карусели берутся только
  элементы, явно помеченные Instagram как фото.
- Reels, видео, обложки видео, Stories, неизвестные типы и чужие публикации исключаются.
- Фото сортируются по дате, а не положению закреплённых публикаций в сетке.

Основной источник — JSON, который Instagram сам загрузил при обычном открытии
страницы, и JSON внутри HTML. Резервный источник — метаданные и элементы самой
публикации с подтверждёнными автором, типом фото и датой. Одна только `og:image`
у публикации не доказывает, что это фото, а не обложка видео.

Для одного профиля — до 3 прокруток и до 18 отдельных страниц публикаций
(до 36 при увеличенном числе товаров). Сбор ограничен этой выборкой:
пропущенные Instagram публикации и абсолютную полноту истории он не гарантирует.
При 401/403/429, запросе входа или challenge партия останавливается.

Имя товара — первая непустая строка подписи, описание — исходная подпись.
Это не распознавание товара на изображении: фото образа, акции или отзыв могут
потребовать исключения при просмотре. Цвета, размеры, цены и остатки не выдумываются.
Товары получают **«Цена по запросу»**; изменить цену и режим можно в панели Delokay.
Наличие обозначено как требующее уточнения. Все новые магазины остаются демо,
реальные заказы отключены.

Необходимый минимум: название, био, сохранённый логотип и 3 фотопубликации с
датами и подписями. При неполных данных статус `needs_review`, публикация не
выполняется. Минимум меняется через `--min-products`, максимум товаров — 12.
Для изменения отбора до публикации можно отредактировать `bundle.json`:
массивы `store.products` и `productSources` должны оставаться попарно согласованными.
После начала публикации не меняйте пакет: существующие изменения автоматически
не перезаписываются. Для повторного сбора до начала публикации переместите
папку конкретного аккаунта из `output/demos/` и запустите сбор заново.

## Публикация в Delokay

Сначала установите в Delokay изменение `priceOnRequest` из ветки
`feat/instagram-personal-demos` репозитория `Mirrorby/f1demo`.
Старый сервер проигнорирует это поле; публичная проверка остановит импорт,
и текст для контакта не будет создан.

Сохраните ключ панели разработчика в переменную окружения без записи в историю
Терминала (bash/zsh):

```sh
printf 'Ключ панели Delokay: '
stty -echo
IFS= read -r PLATFORM_API_KEY
stty echo
printf '\n'
export PLATFORM_API_KEY
export STORE_API_ORIGIN=https://catalog-factory.nikita-karpof.workers.dev
python -m store_finder demos --accounts the.jewelry.shop --limit 1 --language ru --currency BYN --publish
```

Не присылайте ключ в чат. Это тот же `PLATFORM_API_KEY`, который используется
для входа в панель разработчика. Повторный запуск использует локальные фото:
повторно получать временные ссылки Instagram не требуется.

Скрипт создаёт демо, загружает фото через штатный API в R2, обновляет логотип и
добавляет товары. В опубликованном сайте используются `/media/...`, а не временные
CDN-ссылки Instagram. Исходные ссылки и подписи остаются в локальном пакете.
Перед текстом первого контакта проверяются публичные товары, режим цены, логотип
и доступность сохранённых изображений.

После сетевого сбоя повторите ту же команду с той же папкой `--output`.
Скрипт проверяет slug и артикулы исходных публикаций и продолжает импорт.
Активированный магазин, чужой slug или ручные изменения останавливают импорт.
При потере ответа на загрузку изображения может остаться дополнительный
неиспользуемый файл; дубли магазинов и товаров при обычном продолжении не создаются.

## Очередь без ручного ввода аккаунтов

Установите полный набор зависимостей (Python 3.10+) и задайте сервисный ключ Google
из существующей настройки таблицы. GitHub Secrets автоматически на Mac не доступны.
Файл ключа храните вне репозитория:

```sh
python -m pip install -r requirements.txt
export GOOGLE_SERVICE_ACCOUNT_JSON="$(cat /absolute/path/google-service-account.json)"
python -m store_finder demos --from-sheet --limit 3 --language en --currency USD --publish
```

Выбираются только **«Подходит»**, со статусами **«Новый» / «Проверить»** и без
готовой ссылки на демо. Контактированные и исключённые строки не берутся.
После проверки демо заполняются только статус **«Демо готово»** и **«Ссылка на демо»**.
Контакт и комментарий сохраняются. Это явный режим записи двух ранее ручных полей;
обычный парсер продолжает их сохранять. Перед записью строка ищется заново по username.
Не сортируйте и не редактируйте таблицу во время короткой операции записи.

Вместо Google можно использовать локальный `accounts.txt`, по одному username
или URL в строке:

```sh
python -m store_finder demos --accounts-file accounts.txt --limit 3 --publish
```

Максимальная партия — 10 аккаунтов. Дальнейший запуск берёт следующие ещё не
готовые строки таблицы. Без `--publish` получается только локальный просмотр,
строки таблицы не изменяются. Язык интерфейса задаётся `ru`/`en`, исходные подписи
не переводятся; по умолчанию английский и USD, географических фильтров нет.

Первый контакт сейчас **подготавливается**, но не отправляется. Его текст и демо
можно проверить перед отправкой. Автоматическая рассылка и запуск по расписанию
не включены; Chrome и Mac должны быть открыты во время сбора новых профилей.
